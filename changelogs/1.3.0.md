# BetterBedWars v1.3.0 - Changelog

Stability and gameplay release: it fixes the crashes caused by missing sessions, the shop
NPC entity factory and a broken arena taking down the whole game ticker, removes the
generator item duplication and closes a long list of gameplay, shop and map-loading bugs.

### 🛠️ Fixes

**Crashes & stability**
- **Null sessions in listeners**: every listener and helper that reads a `Session`
  (`GameListener`, `SetupListener`, the join handler, spectator forms, shop villagers)
  now checks for `null` before using it. Events without a session (kick during login,
  plugin reload, players created by other plugins) can no longer throw
  `Call to a member function ... on null`.
- **`SessionFactory::removeSession()`**: saving the session on quit is null-safe, so a
  quit without an active session no longer crashes the server.
- **Shop villager entity factory**: the factory closure passed a `Skin` as second
  constructor argument to `ItemShopVillager` and `UpgradesShopVillager`. Villagers extend
  `Entity` (not `Human`), so loading a saved villager threw a `TypeError`. The factory now
  uses `Human(Location, Skin, ?CompoundTag)` only for `Human` subclasses and
  `Entity(Location, ?CompoundTag)` for all the others.
- **`GameHeartbeat` no longer dies on a single broken game**: ticking is wrapped per game.
  A failing game is logged once and skipped instead of cancelling the repeating task,
  which used to freeze every match (countdowns, respawns, generators).
- **Failed arena setup**: `StartingStage` catches errors from `Game::setupWorld()` (missing
  or corrupt world copy), logs them, unloads the half-prepared arena, warns the players
  and puts the game back in the waiting stage instead of starting a dead match.
- **Plugin disable without a game manager**: `onDisable()` no longer dereferences an
  uninitialised `$game_manager` when `onEnable()` failed early.
- **`CreateMapTask`**: the playing world is only unloaded when it is actually loaded
  (`unloadWorld(null)` no longer happens).
- **SQLite provider**: `fetchUserDetails()` is declared `array|false`, matching
  `SQLite3Result::fetchArray()` and the `if($data === false)` check in `loadSession()`.
- **`Session::$loading_data`** is initialised to `false` instead of being uninitialised.

**Gameplay**
- **Generator item duplication removed**: `GameListener::onPickup()` cancelled the pickup
  and added the same stack to *every* player within one block, so two players standing
  near a generator both received the item. The override was removed: pickups use the
  vanilla path, so exactly one player receives the item and the remainder stays on the
  ground.
- **Item merges no longer destroy items**: when the merged stack exceeded the per-item
  limit the plugin used to despawn the merging entity *and* cancel the merge, deleting
  items. It now only cancels the merge, so the two stacks simply stay separate.
- **Blocks can be placed in your own base**: placement was blocked inside any team claim,
  including the player's own. The check now resolves the claim owner and only blocks
  claims of other teams (a claim outside the team zone is also handled now).
- **Beds can no longer be broken as normal blocks**: when the bed block did not match the
  stored bed position the event was not cancelled, so the bed disappeared without the team
  losing its respawns. The break is now cancelled, and the position check tolerates the
  one-block offset between maps created in-game and maps read from disk.
- **Bed destruction breaks the real bed**: `Team::breakBedBlock()` now locates the bed at
  the stored position (or one block above/below) instead of blindly breaking the stored
  block, and does nothing when the game world is not available.
- **No joining a full or already-started match**: `Game::addPlayer()` refuses full games,
  running matches and the ending phase, and informs the player, instead of dropping
  someone into a match with no team, no spawn and no respawn.
- **Win and coins are awarded once**: `EndingStage` handed them out in `onJoin()`, so
  joining a match while it was ending granted a free win and 140 coins. Rewards are now
  given once in `onStart()` to the actual players.
- **Team removal no longer removes the wrong member**: `Team::removeMember()` used
  `unset($members[array_search(...)])`, so a failed search (`false`) removed index `0`.
  The bed is also destroyed only once (no repeated "BED DESTROYED" titles).
- **Kills are not credited to players who left**: a stale "last hit" (10 second window)
  could reward a player who already left the game, or the victim himself.
- **No item duplication on death**: the inventory is cleared on every death path,
  including when the match is already ending (previously the items dropped to the killer
  stayed in the dead player's inventory).
- **Sleeping in a bed** is blocked again only for players taking part in a game, not for
  every player on the server.
- **Shop villagers** with no session no longer crash, and the join NPC can no longer be
  damaged or killed by a normal hit (the bedrock removal for operators still works).
- **`GameSettings::apply()`** returns early when the session has no team (it used to call
  `getTeam()` on `null`), and `getMaterial()` has a default case instead of an
  `UnhandledMatchError`.
- **Pickaxes no longer get Sharpness**: the tier 3 sharpness enchantment is applied to the
  axe only, where it actually has an effect.
- **Teams without generators**: `Team::jsonSerialize()` used `generators[0]` and crashed
  when a team had none; it now falls back to the team spawn point.
- **Scoreboard with no next event**: `PlayingStage::getNextEvent()` is `?Event` and the
  scoreboard skips the event line instead of dereferencing `null`.
- **`updatePlayEntities()`** no longer crashes when the server has no default world.
- **MySQL stats earned during the async load** are added to the stored values instead of
  being overwritten by them when the query completes.

**Shop**
- **Armor purchases**: products that only run a purchase listener (the armor category
  uses an air item) failed the "inventory full" check and could not be bought. Air
  products now skip the inventory check and the item is not added.
- **Unknown upgrades** now fail with a clear `InvalidArgumentException` instead of a
  `TypeError`, and the dead `canPurchase()` (which applied the upgrade *and* `purchase()`
  applied it again) was removed.
- **Tool prices/ores** have default match arms, so an unexpected tier can no longer throw
  `UnhandledMatchError`.

**Maps & data**
- **Startup is resilient**: a map whose world is missing is logged and skipped instead of
  aborting plugin startup, and a missing/invalid `maps.json` is treated as empty.
- **Deleting a map** no longer unloads a waiting world that other maps still use.
- **`maps.json` is always written as a JSON array** (`array_values()`), so deleting a map
  no longer produces an object with gaps in the indexes.

### 🗑️ Removed
- `GameListener::onPickup()` and its now-unused imports (`EntityItemPickupEvent`,
  `ItemEntity`, `NetworkBroadcastUtils`, `EntityEventBroadcaster`).
- `UpgradeProduct::canPurchase()` (dead code: it levelled the upgrade up as a side effect
  of a check, while `purchase()` levelled it up again).

*Note: design-dependent items reported in the code review are intentionally unchanged:
`Area::isInside()` still ignores Y (2D zones so traps trigger while building upwards),
dropping resources on the ground is still allowed, explosions still deal no base damage,
and the entity save-id is still derived from the class name.*
