# BetterBedWars v1.2.0 - Changelog

## ✨ Completed TODOs
- **Final kill detection** — the killer now gets a bigger coin reward (40 instead of 8) plus a "FINAL KILL!" title/broadcast when the victim can't respawn (their bed is destroyed).
- **Trap sound** — triggering a trap now plays a sound to the defending team (`mob.enderdragon.growl` for the Alarm Trap, `mob.wolf.growl` otherwise).
- **`Mode` enum for players-per-team** — replaced the raw `int $players_per_team` with a backed enum (`Mode::SOLO = 1`, `DUOS = 2`, `SQUADS = 4`) across maps, builders, queue forms, the NPC entity and `GameUtils::getMode()`.
- **`ShopId` enum for shops** — replaced the string constants (`Shop::ITEM`, `UPGRADES`, `TRACKER`) with a backed enum used by `Shop`, `ShopFactory` and all shop callers.
- **Deduplicated maps.json code** — the read/append/write logic duplicated in `CreateMapTask` and `DeleteMapTask` now lives in `MapFactory::readMapsData()` / `MapFactory::writeMapsData()` (also reused by `MapFactory::init()`).

## 🛠️ Bug Fixes

### Crashes
- **Crash on every player quit** — `SessionListener::onQuit` (HIGHEST priority) removed the session before `GameListener::onQuit` could read it, causing a `null->getGame()` error. Execution order is now correct and a null guard was added.
- **`Game::reset()` infinite loop** — when a map had more than 5 games, the game stayed registered and its expired EndingStage kept submitting `RemoveGameTask` every tick (repeated deletions of the same world). The game is now removed from the GameManager immediately.
- **"It's a trap" purchasable multiple times** — the trap's name ("It's a trap!") didn't match the product's name ("It's a trap"), so `hasTrap()` never returned true. Names are now aligned.
- **Setup items with uppercase letters ("Claiming_wand", "Bed_position", ...)** — the registry lookup didn't use `strtolower` and threw an exception while setting up areas. The lookup is now case-insensitive.
- **`LoadSessionTask` (MySQL)** — `$rows[0]` was accessed without checking for an empty result. Added a guard and `finishLoad()`.
- **`CreateMapTask` stored a live `World` object in the AsyncTask** — the PM5 `World` class is not serializable (it holds the Server, worker pool, file handles, ...). `MapBuilder` now stores only the waiting world's folder name and resolves the live `World` in `build()`.
- **`DeleteMapTask` stored a live `World` object in the AsyncTask** — same serialization issue: `Map` now excludes the waiting world from serialization and the task stores its folder name.
- **Boss bar crash on player join** — newer PMMP 5 releases changed `BossEventPacket::show()` (no more `darkenScreen` flag; the color moved to the 4th argument), causing a `TypeError` on every hub teleport. The packet is now built property-by-property, which works on both older and newer PMMP 5 releases.
- **Crash when using non-BedWars items in setup mode** — newer `pocketmine/nbt` releases throw `NoSuchTagException` when a tag is missing (older versions returned an empty string), so interacting with/destroying a plain item while creating a map crashed the server. BedWars item lookups now use `getTag()` + an `instanceof StringTag` check (`SetupListener`, `ItemListener`); this also protects against items carrying a wrong-typed `bedwars_name` tag (possible with modified clients).

### Logic
- **Setup and game items only reacted to air clicks** — on newer PocketMine-MP releases `PlayerItemUseEvent` is fired only when right-clicking the air, so right-clicking a block did nothing: the "Done" item that closes the villager step, "Configuration", "Create map", "Exit setup" and the spectator/game items (leave game, teleporter, ...) were effectively unusable. `ItemListener` now also handles `PlayerInteractEvent` (right-click on a block) and triggers the same item action; the handler is marked `@handleCancelled` so it works for spectators as well. Block interactions are intentionally not cancelled, so opening a chest while holding an item keeps working.
- **Scoreboard compatibility with newer PMMP 5 releases** — fake-player score entries now use the newer `ScorePacketEntryAction` enum and `SetScorePacket::create()` while retaining compatibility with older PMMP 5 versions.
- **Tracker Shop was unusable** — it required your own bed to be destroyed as well before you could track a player. Your own team is now skipped in the check.
- **Ineffective claim protection** — it checked the block placed against instead of the blocks actually placed. It now checks every block in the transaction.
- **Placed TNT never ignited** — it used the (null) block position from the transaction. It now uses the real placement coordinates.
- **Unsafe `unset($arr[array_search()])`** — when the session wasn't found, `false` was cast to `0` and the wrong player was removed. Added an index guard.
- **`loading_data` race (MySQL)** — the flag was cleared right after the async submit, causing the load to write the freshly-read data back to the database. `finishLoad()` is now called once loading completes.
- **`ColorUtils::getDye`** — `match` with no default arm: crash on unknown colors. Added a `DyeColor::WHITE` default.
- **`Session::kill()` without a team** — crash on respawn. The player now becomes a spectator.
- **Incomplete map deletion** — the deleted map's games stayed active and its waiting world stayed loaded. Added `removeGamesByMap()` and waiting world unload.
- **Listener side effects server-wide** — `onExhaust` (hunger), `onExplosionPrime` (explosion radius) and `onMerge` (item stack cap) affected the whole server, not just BedWars games. They're now scoped to BedWars worlds.
- **Spectator settings never persisted (SQLite/MySQL)** — changes made in the spectator settings form were lost on logout: `saveSession()` was a no-op in SQLite and missing in MySQL. Both providers now save them (new `UpdateSpectatorSettingsTask` for MySQL).
- **Stale scoreboard for spectators** — spectators kept the waiting-room scoreboard. They now get the `GameScoreboard`.
- **Chest/bed interactions without a team** — possible crash for teamless players. Added `hasTeam()` guards.
- **Unvalidated map name** — names with characters illegal for folder names (`\ / : * ? " < > |`) broke world copying. Invalid characters are now rejected.

### Robustness
- **Source-tree dependency loading** — running the plugin directly from its source folder now loads bStats and EasyUI without registering the bundled PocketMine-MP classes, avoiding conflicts with the server's PocketMine-MP version.
- **Version-independent protocol packets** — `PlaySoundPacket::create()` (extra required parameters), `MobArmorEquipmentPacket::create()` (added `body` slot) and `TypeConverter::getInstance()` (removed) all broke on newer PMMP 5 builds. Sound, armor and invisibility packets are now assembled by setting their public properties (with `property_exists()` guards for optional fields), and the invisibility snapshot uses a protocol-level null `ItemStack` instead of the removed singleton.
- **`Session`** — `scoreboard` and `spectator_settings` weren't initialized in the constructor: possible "uninitialized property" errors with the async MySQL provider. They're now initialized with default values.
- **`ItemListener` / `BedwarsItems::get()`** — exception on unknown names. Now a safe lookup with a null fallback.
- **`JsonProvider` / `SqliteProvider`** — defaults for missing data (`?? 0`, `?? []`, `fetch === false` guard).
- **`MapFactory`** — corrupted or empty `maps.json`: added `?? []` on decode.
- **`PlayingStage::tick`** — null guard on `next_event`.
- **`CreateMapItem` / `ConfigurationItem`** — null guards on `mapSetup`.
- **`PlayBedwarsEntity`** — `players_per_team` is now read defensively (`getInt(..., 1)` + `Mode::tryFrom(...) ?? Mode::SOLO`): NPC data saved by older plugin versions (or damaged data) can no longer crash the server while a chunk is loaded.

## 🔩 Build & Dependencies
- **BetterLite server packages** — the dependency on the vanilla server (`pocketmine/pocketmine-mp`) was replaced with `betterlite/pocketmine-mp`, bringing in the BetterLite `bedrock-protocol`, `bedrock-data`, `bedrock-block-upgrade-schema`, `bedrock-item-upgrade-schema` and `xoroshiro128pp` packages: the plugin is now built against the same libraries the server runs.
- **Pharynx `replace` workaround** — Pharynx 0.3.x cannot follow Composer's `replace` mechanism, so `build/create-vendor-stub.php` (run automatically by `composer build`) materialises a metadata stub for the replaced package.
